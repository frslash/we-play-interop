# Blocked: a real person signs up from Keyring and enters the encrypted room

Step b13d0a211318 is done when a real person, with keys they hold, signs up from Keyring, gets a membership pass and
enters the encrypted room. A builder can't be that person, and the room's side is not yet open to a real wallet.

## What stops it

1. **The join desk is not reachable.** `src/server/join.js` (the invite, the signed join, a member's yes, the pass,
   the leaf gate) says at its top: test members and test values only until Security's gate opens, and not wired into
   the server routes yet. No route or page uses it (the new test checks that).
2. **A wallet has nowhere to answer.** The README ("Join on your phone"): the room's DID is a `did:key` with no
   DIDComm service, and the room has no DIDComm inbox, so Keyring can read the invitation but can't send the join.
   It has not been tried with a real wallet.
3. **Security's gate** (named in `join.js`): a second implementation to check against, Security's code read, and the
   call on lost keys. Opening the desk to real people waits on those.
4. **A real person with Keyring**, and a member of the room to say yes. Eli, Hyphy and Maximilian's Claude each said
   this belongs with Keyring's side.

## What this pull request adds

`test/keyring-signup-rehearsal.test.js`, with test keys only:

- the whole path in one go: a member's invite, a join signed with the joiner's own key (pending, no pass), a member's
  tap issuing the pass (for the joiner's DID, short-lived, no admin), the joiner's MLS leaf bound by its DID and
  verified, the epoch key released to it, and the joiner writing, listing and reading back a sealed note in the
  sealed host; someone else presenting the pass is refused;
- a check that no server route or page reaches the join desk yet. When the desk is wired in, that check fails on
  purpose: update this note then.

This pull request changes no code that runs.

## What would unblock it, in order

- Security's gate decided for real people (or an explicit "test room only" go-ahead).
- A step that wires the desk into routes and gives the room a DIDComm inbox (or another channel Keyring speaks).
- Keyring's side: a person signs up with their own keys while a member of the room is there to say yes.
